# 商业产品 V1.0 开发计划

> **定位**: 阶段 **D（D-0～D-4 + D-3）全部完成后** 启动的 **商业产品级** 全面开发计划。  
> **不是 Demo 收尾**，目标是可对内/对外 **试售与持续运营** 的下载中继商品（卡密订阅模型）。  
> **关联**:  
> - 当前迭代：[`POST_MVP_PLAN.md`](../POST_MVP_PLAN.md)  
> - 阶段 D 技术底座：[`STAGE_D_PLAN.md`](./STAGE_D_PLAN.md)  
> - 商业蓝图：[`business_landing_architecture.md`](../business_landing_architecture.md)  
> - 发行：[`release.md`](./release.md)  
>
> **状态**: 📋 计划已定稿；**编码起点 = D-4 ✅ 且 D-3 ✅ 之后**（当前 D-4/D-3 未完成时禁止提前把本计划当进行中主线，除非专项插队）。

## 0. 路线总图

```text
[已完成] 工程 0/A/B/C + 商业底座 D-0/D-1/D-2
    ↓
[进行中] D-4 限流与日配额
    ↓
[随后]   D-3 签名/设备池（产能）
    ↓
════════ 阶段 D 出口：技术底座就绪 ════════
    ↓
[本计划] 商业产品 V1.0 全面开发（E 阶段）
    E0  发布门禁与履约质量
    E1  多用户隔离与数据归属
    E2  客户端商业闭环
    E3  生产安全默认
    E4  最小运营能力
    E5  可观测性与备份
    E6  正式发行与上线清单
    ↓
[之后]   V1.1+ 支付直连 / 管理后台 / 多机 Job 等（非 V1.0 必做）
```

**原则**

1. **履约优先于功能堆叠**：不能稳定出片/出书，不叫商业产品。  
2. **付费用户路径必须闭环**：注册 → 兑卡 → VIP → 下载 → 取文件，UI 与 API 一致、错误诚实。  
3. **开发旁路保留**：`AUTH_MODE=dev` + API Key 仅限运维/CI，**生产默认 dual 或 jwt_only**。  
4. **合规与风控写进产品**：版权/ToS 提示、滥用处置、可封禁，不靠口头。  
5. **每个 E 切片可独立验收、独立上线开关**。

## 1. 阶段 D 出口标准（进入本计划的前提）

以下 **全部满足** 才算「4 阶段商业底座完成」，可正式开 E：

| ID | 出口项 | 验收 |
|----|--------|------|
| X1 | D-0～D-2 | 用户/JWT/卡密/VIP 测绿（现已基本满足） |
| X2 | **D-4** | 限流 + VIP 日配额；ops 豁免配额；pytest + smoke 不误杀 |
| X3 | **D-3** | 签名池或等价多节点调度：健康检查、租约/排队、失败可重试、文档可部署 |
| X4 | 双模式可跑 | `dev` 下 Key e2e 脚本可跑；`dual` 下 JWT+VIP 人工路径可跑 |
| X5 | 计划文档 | `STAGE_D_PLAN` / `POST_MVP_PLAN` 勾选 D-3/D-4 完成 |

**未满足 X2/X3 时**：只允许做 E 的设计细化与原型，**不宣称进入商业 V1.0 全面开发**。

## 2. 商业 V1.0 成功标准（DoD）

对外可宣称「商业 V1.0」当且仅当：

| ID | 标准 |
|----|------|
| C1 | **履约门禁**：红果、番茄各 ≥1 条固定 e2e（或等价日检）进入发布检查；失败阻断发版 |
| C2 | **付费闭环**：客户端完成 登录 → 兑卡 → 见 VIP → 建任务 → 看进度 → 打开/下载产物 |
| C3 | **隔离**：Job 与产物列表按用户隔离；用户 A 不能通过 file_id 读 B 的文件 |
| C4 | **防刷**：限流 + 日配额生效；注册/登录防爆破 |
| C5 | **产能**：签名请求进池；节点 down 有明确错误，不Silent 挂死 |
| C6 | **生产安全**：默认 API_KEY/JWT_SECRET 在 `AUTH_MODE=dual|jwt_only` 且监听非本机时 **拒绝启动** 或强制强密钥 |
| C7 | **运营最小集**：作废卡密批次、禁用用户；发卡脚本+操作说明 |
| C8 | **可运维**：日志级别可配；备份 `app.db`+配置说明；版本号全链路一致 |
| C9 | **诚实错误**：全链路无假成功 Toast；429/403/502 文案可被客服理解 |
| C10 | **发行物**：正式包（建议 noconsole 或日志文件）+ `docs/release.md` 商业安装专章 |

## 4. E0 — 发布门禁与履约质量

### 目标

把「能下」变成 **可重复、可门禁的发布条件**。

### 工作项

| 任务 | 说明 | 状态 |
|------|------|------|
| E0-1 | 固定样例：红果 1 剧 1 集、番茄 1 书 1～3 章（文档写死 ID/命令） | ✅ |
| E0-2 | CI 或本地 `scripts/ci_smoke.ps1|sh`：dev Key → smoke + 双平台 e2e（环境 secret 注入） | ✅ |
| E0-3 | 平台错误码规范化：签名失败/会话过期/限流/节点忙 → 稳定 `detail` 前缀 | ✅ |
| E0-4 | Job 失败原因落库/落 JSON，UI 只展示服务端文案 | ✅ |
| E0-5 | 发布检查表：`docs/release_gate.md`（e2e 绿、无默认密钥、版本号） | ✅ |

### 验收

- [x] 干净环境按文档可复现双平台至少各 1 次成功落盘  
- [x] 发版 checklist 必须勾 e2e  
- [x] 失败场景人工可读、可归类  

### 预估

3～5 人日（含环境脚本；不含永久稳定逆向）。

## 6. E2 — 客户端商业闭环

### 目标

桌面端 **不用 curl** 即可完成付费用户全流程。

### 工作项

| 任务 | 说明 |
|------|------|
| E2-1 | 登录/注册页（或设置内账号区）；token 存 localStorage；退出清除 |
| E2-2 | 设置：API Base、可选 Key（仅高级/运维）、账号态切换 |
| E2-3 | 卡密兑换对接真 API；展示 `vip_expires_at`；失败不关弹窗装成功 |
| E2-4 | 非 VIP 点下载：引导兑卡；403 原样展示 |
| E2-5 | 429/502 分类提示（配额/限流/签名忙） |
| E2-6 | 标题栏/关于页版本 = 服务端 `__version__`（可 /health 拉取） |
| E2-7 | dual 为商业默认文档路径；dev 仅开发说明 |

### 验收

- [ ] 纯 UI：注册→登录→兑卡→下 1 集/章→打开产物  
- [ ] 无假成功  
- [ ] Key 模式仍可用于运维（隐藏或高级开关）  

### 预估

4～7 人日。

## 7. E3 — 生产安全默认

### 目标

### 工作项

| 任务 | 说明 |
|------|------|
| E3-1 | `AUTH_MODE=dual|jwt_only` 且 `JWT_SECRET` 为默认 → **拒绝启动**（或仅 127.0.0.1 允许+警告） |

## 12. 非目标（V1.0 不做）

| 不做 | 原因 |
|------|------|
| 微信/支付宝直连支付 | 发卡网即可；支付合规成本高 |
| 完整 Web 运营后台 | E4 CLI/最小 API 足够 V1 |
| 多机 Celery 集群 | 单机+池先验证模型 |
| 保证 100% 绕过平台风控 | 不可承诺；产品文案禁止「永久稳定」 |
| 去除所有逆向依赖 | 业务现实不允许 |

## 13. 风险登记

| 风险 | 影响 | 缓解 |
|------|------|------|
| 平台改签/改协议 | 全站停摆 | 错误分类、热修适配、池版本钉扎、合同/文案免责 |
| 签名节点被风控 | 产能骤降 | 多节点、冷却、降级提示 |
| 法律/版权 | 业务风险 | 仅学习研究声明、地域与用户协议、拒绝公开传播站 |
| 默认配置上生产 | 被打穿 | E3 强制 |
| 范围蔓延回 Demo 功能 | 永远发不了 V1 | 严格 E0→E6 顺序与 DoD |
