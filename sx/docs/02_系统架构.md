# 系统架构设计

## 1. 逻辑架构

```
┌──────────────────────────────────────────────────────────────────┐
│                         闪现 Host App                            │
│  Splash · 激活 · Main(Tab) · 各 Settings · 应用列表/详情          │
├──────────────────────────────────────────────────────────────────┤
│  Domain / Config                                                 │
│  LocationConfig · DeviceProfile · NetworkProfile · CameraConfig  │
│  LicenseManager · TimeGuard · SxPrefs (分身级 Profile)           │
├────────────────────────────┬─────────────────────────────────────┤
│  SandboxEngine (接口)      │  SpoofRuntime (接口)                │
│  install/launch/clone/...  │  定位注入 · 设备/网络/相机 Hook     │
├────────────────────────────┴─────────────────────────────────────┤
│  BlackBox Engine Fork          │  Hook Impl (Pine / BB hooks)    │
│  多开 · IO 隔离 · 进程代理      │  读 Profile → 改返回值/喂帧      │
└──────────────────────────────────────────────────────────────────┘
```

---

## 2. 进程模型（概念）

对齐 xh/VA 系常见模型（BlackBox 实现细节以实际引擎为准）：

| 进程 | 职责 |
|------|------|
| 主进程 | UI、配置、授权、引擎管理端 |
| 引擎服务进程（类似 `:va_core` / BB server） | 虚拟包管理、启动分发、IPC |
| 虚拟客户端进程 `:pN` | 运行分身 App；加载 Hook |

```
用户点击「微信 #2」
    → Host UI
    → SandboxEngine.launch(pkg, userId=1)
    → Engine 创建/复用虚拟进程
    → SpoofRuntime.installHooks(userId, pkg)
    → 目标 Application 在虚拟环境启动
```

## 3. 配置与数据流

### 3.1 配置作用域

| 作用域 | 说明 | 存储 Key 示例 |
|--------|------|----------------|
| 全局 Global | 默认伪装，未单独设置的分身继承 | `profile/global/*` |
| 分身 Instance | `packageName + userId` 覆盖全局 | `profile/{pkg}/{userId}/*` |

与 xh 文案对应：

- `title_user_device` → 全局设置  
- `title_app_device` / `app_settings_content` → 独立设置  

### 3.2 配置下发路径

```
UI 保存
  → SxPrefs / 数据库写入（Host 私有目录）
  → 通知 Engine / 广播 CONFIG_CHANGED
  → 虚拟进程内 ConfigReader 热更新或下次启动加载
  → Hook 使用最新 Profile
```

**注意：** 虚拟进程读配置需走引擎 IPC 或世界可读/XSharedPreferences 策略；禁止假设与 Host 同进程。

### 3.3 沙箱数据隔离

概念路径（最终以 BlackBox 实际目录为准，语义对齐 xh）：

```
/data/data/com.sx.app/
  ├── files/sx_config/          # 宿主配置
  └── virtual/                  # 引擎数据根（示例名）
        └── data/user/{userId}/{package}/
```

## 4. 模块边界

| 模块 | 依赖 | 禁止依赖 |
|------|------|----------|
| `ui.*` | domain、sandbox-api | 直接 import BlackBox 实现类 |
| `sandbox.api` | 无 UI | — |
| `sandbox.bb` | BlackBox、api | ui |
| `spoof.*` | data models、api | 具体 Activity |
| `license` | util、prefs | sandbox 实现 |
| `service.MockLocation` | LocationConfig | 可选；沙箱内 Hook 为主通道 |

## 5. 双通道定位策略

| 通道 | 机制 | 适用 |
|------|------|------|
| A. 进程内 Hook | 改 `Location` get/isFromMock、Listener 回调 | 沙箱内目标 App（主） |
| B. 系统 TestProvider | `MockLocationService` 50ms `setTestProviderLocation` | 需开发者选项；作辅助/调试 |

产品默认：**通道 A 必做**；通道 B 可选增强（对齐 xh `FackLocService` 思路）。

## 6. 安全架构（一期）

```
卡密输入 → 解析到期 → 绑定 deviceId
         → 签发 token = base64(payload) + HMAC
         → 本地存储
校验：签名 + deviceId + TimeGuard.now() < expire
TimeGuard：max(系统时间, 本地 stamp, 网络 Date头)
```

加固、VMP、防二次打包：发布阶段见开发计划 Phase 4。

## 8. 关键质量属性

| 属性 | 目标 |
|------|------|
| 分身冷启动 | 可接受范围内接近原生（视引擎） |
| 定位更新周期 | 可配置，默认 **50ms** 语义（实现可用 50–200ms 视耗电） |
| 配置生效 | 保存后重新进入分身必生效；运行中热更新 Best-effort |
| 崩溃隔离 | 分身崩溃不拖死 Host UI |

---

## 9. 架构原则

1. **引擎可替换**：只依赖 `SandboxEngine`  
2. **规格对齐 xh，实现自有**  
3. **分身级配置优先**  
4. **先跑通多开，再加深伪装**  
5. **合规源码，不引入未授权 VA**
