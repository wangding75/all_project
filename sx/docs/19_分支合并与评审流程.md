# 分支、合并与评审流程

| 版本 | v1.0 |
|------|------|
| 约定 | **开发完成 → 先合并 main → 再完整 review 查漏** |

---

## 1. 标准流程

```text
1. 从 main 拉 feature/sx-phaseN-xxx
2. 开发 + 自测（模拟器 → 通用真机）
3. 阶段评审 PASS（可修阻断后复审）
4. 提交干净 commit（仅 sx/ 相关）
5. 合并进 main（优先 fast-forward 或 merge commit）
6. 在 main 上做一次「完整 review 检查清单」（本文 §3）
7. 通过后才开下一阶段分支
```

**禁止：** 评审 PASS 后长期只停在 feature、不合 main；或在未合 main 的脏分支上叠下一 Phase。

---

## 2. 合并前检查

- [ ] 工作区仅含本阶段意图内改动  
- [ ] `assembleDebug` 通过  
- [ ] 无 `app/build`、`.gradle` 等产物进库（依赖 `sx/.gitignore`）  
- [ ] 阻断评审项已关闭  

---

## 3. 合并后完整 Review 清单（查漏）

### 3.1 范围与文档

- [ ] 本阶段 Epic 与 docs 状态一致  
- [ ] 未误带其它 monorepo 子项目无关改动（或有意合并时单独说明）  
- [ ] 下一阶段入口文档仍有效  

### 3.2 架构

- [ ] UI 不直接依赖 BlackBox / Pine 内部 API  
- [ ] `SandboxEngine` / Provider 边界在  
- [ ] 关键配置 MODE_PRIVATE / Provider 安全策略在  

### 3.3 功能门禁（已完成阶段）

| 阶段 | 抽查 |
|------|------|
| Phase 0 | 启动、三 Tab、Fake 可切换路径存在 |
| Phase 1 | blackbox 初始化、install/launch/clone 代码路径 |
| Phase 2 | `getHostPkg`、ConfigProvider、Hooks、Probe |
| Phase 3 | 相机/授权（未完成则 N/A） |
| Phase 4 | 发布项（未完成则 N/A） |

### 3.4 构建

- [ ] `main` 上 `./gradlew :app:assembleDebug` 通过  

### 3.5 已知问题

- [ ] 兼容表 / 笔记未过时  
- [ ] 商业化仍等四阶段后（docs/14、15）  

---

## 4. 一句话

> **阶段开发完成并评审通过后，必须先合 main，再在 main 上做完整查漏 review，然后才进入下一阶段。**
