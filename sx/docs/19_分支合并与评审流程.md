# 分支、提交与评审流程

| 版本 | v1.1 |
|------|------|
| 生效 | 2026-07-21 |
| 约定 | **固定在 `main` 开发；执行完必须提交；Review 只读已提交代码** |

---

## 1. 现行标准流程（强制）

```text
1. 检出 main，保持与主干一致后开发
2. 按阶段/任务实现 + 自测（模拟器 → 通用真机）
3. 执行完成后：Agent / 开发者必须 git commit（仅 sx/ 相关意图改动）
4. 宣称「完成」时：工作区应干净，或明确列出未提交项（默认不允许带未提交关键代码申请 review）
5. Review：只读取 git 已提交内容（指定 commit / main HEAD），不以未暂存工作区为准
6. Review PASS 后：可直接进入下一任务；若 REJECT：在 main 上修并再次提交后再复审
```

### 1.1 分支策略

| 策略 | 说明 |
|------|------|
| **默认** | **始终在 `main` 上开发与提交** |
| 可选 | 仅当多人并行且冲突风险高时，临时 `feature/*`，完成后 **当日合回 main**，不长期分叉 |
| 禁止 | 长期 feature 堆多阶段、Review 通过却不落库 |

### 1.2 Agent 义务

| 时机 | 必须做 |
|------|--------|
| 完成一轮开发/修复任务 | **`git add` 相关文件 + `git commit`**，回报 commit hash |
| 申请 Review / 用户要求 review | 说明 **基于哪个 commit**；优先 `git show` / 读该提交中的文件 |
| 发现未提交关键改动 | 先提交或请用户确认，**不得**用脏工作区冒充已交付 |

### 1.3 Review 义务

| 规则 | 说明 |
|------|------|
| 读已提交代码 | `git log` / `git show <hash>` / 检出后的仓库树以 **HEAD 已提交** 为准 |
| 不默认信任工作区 | 未 `commit` 的 diff 可提示「未入库，不纳入本轮验收」 |
| 通过后 | 记录「PASS @ commit」；下一阶段基于该点继续 |
| 现阶段测试门禁 | 见 **docs/24**：默认 **不强制** 模拟器/真机全路径；优先 **代码齐 + 可打包安装启动**；目标 App（含是否钉钉）**最后统一测** |
| 禁止 | 未测写设备 PASS；未立项却宣称「默认支持钉钉」 |

## 2. 提交前检查

- [ ] 当前分支为 `main`（或即将合回 main 的短期 feature）  
- [ ] 改动范围符合本任务（优先 `sx/`）  
- [ ] `assembleDebug` 通过  
- [ ] 无 `build/`、`.gradle` 等产物（见 `sx/.gitignore`）  
- [ ] commit message 说明阶段/修复点  

---

## 3. 提交后完整 Review 清单（查漏）

### 3.1 范围与文档

- [ ] 本阶段 Epic / Backlog 状态与提交内容一致  
- [ ] monorepo 未误带无关项目（或 commit 中已说明）  
- [ ] 下一阶段入口文档仍有效  

### 3.2 架构

- [ ] UI 不直接依赖 BlackBox / Pine 内部 API  
- [ ] `SandboxEngine` / Provider 边界在  
- [ ] 关键配置 MODE_PRIVATE / Provider 安全策略在  

### 3.3 功能门禁（已完成阶段）

| 阶段 | 抽查（在已提交代码中） |
|------|------------------------|
| Phase 0 | 启动、三 Tab、Fake 切换路径 |
| Phase 1 | BB 初始化、install/launch/clone |
| Phase 2 | `getHostPkg`、ConfigProvider、Hooks、Probe |
| Phase 3 | 相机/授权门闸 |
| Phase 4 | 发布项 |

### 3.4 构建

- [ ] 在 **已提交 HEAD** 上 `./gradlew :app:assembleDebug` 通过  

### 3.5 已知问题

- [ ] 兼容表 / 笔记未过时  
- [ ] 商业化仍等四阶段后（docs/14、15）  

---

## 4. 与历史流程的差异

| 旧（v1.0） | 现（v1.1） |
|------------|------------|
| 每阶段 feature 分支再合 main | **默认 main 直开** |
| 先合再 review | **先 commit，review 读 commit**；main 即主线 |
| 可长期 feature | **禁止**多阶段堆在未入库分支 |

---

## 5. 一句话

> **后续固定在 main 开发；每轮执行完必须提交；Review 只验收已提交代码。**
