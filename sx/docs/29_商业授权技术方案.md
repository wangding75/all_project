## 1. 核心决策

| 决策项 | 结论 |
|--------|------|
| 服务端形态 | **本项目自建服务端**（独立部署，管理卡密全生命周期） |
| 三方卡网角色 | **仅负责收款+自动发货**，通过回调从本服务端取卡密，不直接与客户端通信 |
| 客户端对接 | **只和本项目服务端通信**，不直接调任何三方卡网接口 |
| 卡密策略 | 简单策略，时长自定义；1 台设备绑定 |
| 设备绑定 | AndroidID SHA-256 哈希 |
| 本地存储 | 当前为 `MODE_PRIVATE SharedPreferences`；静态加密列入 P-B |
| 离线策略 | 本地 Token 到期前可用，依赖 TimeGuard 可信时间 |
| DEV 卡密 | 仅 debug 包保留，release 拒绝 |

## 2. 三实体架构

```
┌──────────────────┐      ┌─────────────────────────┐      ┌──────────────────┐
│   三方卡网        │      │      本项目服务端          │      │  客户端（Android）│
│（爱发卡/发卡网等）│      │（独立部署，项目自建）       │      │                  │
└──────────────────┘      └─────────────────────────┘      └──────────────────┘

  用户付款
      │
      │ 自动发货 Webhook
      └──────────────────► POST /api/cards/deliver
                           服务端生成/取出卡密
                           返回 {"card_key":"SX-XXXX"}
      ◄──────────────────
      │ 卡网把卡密发给用户
      
                                                              用户手动输入卡密
                                                                     │
                                            POST /api/license/activate
                                            body: {card_key, device_id, sign}◄─┘
                                            服务端校验卡密 + 绑定设备
                                            返回 {token, expire_at}
                                                              ────────►
                                                              应用私有存储 Token

                                            GET /api/license/verify   ◄─── 启动时后台刷新
                                            header: Authorization: Bearer {token}
                                            query: device_id={deviceId}
                                            返回 {valid, expire_at, token}

                                            POST /api/license/unbind  ◄─── 管理员后台操作
                                            （解绑设备，允许用户换机）
```

## 4. 本项目服务端设计

### 4.1 当前技术选型

| 项 | 建议 | 说明 |
|----|------|------|
| 语言/框架 | Python FastAPI | 当前服务端实现 |
| 数据库 | SQLite | 存卡密、设备绑定、激活与发货幂等记录 |
| 部署 | 独立服务；生产由 HTTPS 反向代理保护 | 客户端 Release 拒绝明文 HTTP |
| 激活请求 | `MD5(card_key + device_id + CLIENT_SIGN_SECRET).upper()` | 兼容当前客户端协议；不能代替 TLS |
| Token | RSA-SHA256 | 私钥只在服务端，客户端内置公钥 |

### 4.2 数据模型

```sql
-- 卡密表
CREATE TABLE cards (
    id          INTEGER PRIMARY KEY,
    card_key    VARCHAR(64) UNIQUE NOT NULL,   -- 如 SX-XXXX-XXXX-XXXX
    duration_days INTEGER NOT NULL,            -- 有效天数（-1=永久）
    status      VARCHAR(16) DEFAULT 'unused',  -- unused/activated/expired/revoked
    created_at  BIGINT NOT NULL,
    batch_id    VARCHAR(32)                    -- 批次 ID，便于管理
);

-- 激活记录表
CREATE TABLE activations (
    id          INTEGER PRIMARY KEY,
    card_key    VARCHAR(64) NOT NULL,
    device_id   VARCHAR(64) NOT NULL,          -- SHA-256 of AndroidID
    activated_at BIGINT NOT NULL,
    expire_at   BIGINT NOT NULL,               -- Unix ms；-1=永久
    is_active   BOOLEAN DEFAULT TRUE,
    UNIQUE(card_key)
);

-- 三方发货幂等表
CREATE TABLE deliveries (
    order_id     VARCHAR(128) PRIMARY KEY,
    product_id   VARCHAR(64) NOT NULL,
    quantity     INTEGER NOT NULL,
    cards_json   TEXT NOT NULL,
    created_at   BIGINT NOT NULL
);
```

### 4.3 API 接口清单

#### 面向客户端

**激活卡密**
```
POST /api/license/activate
Content-Type: application/json

{
  "card_key": "SX-XXXX-XXXX-XXXX",
  "device_id": "sha256_of_android_id",
  "sign": "MD5(card_key+device_id+CLIENT_SIGN_SECRET).upper()"
}

响应 200:
{
  "code": 200,
  "msg": "激活成功",
  "data": {
    "token": "{base64url_payload}.{rsa_sha256_signature}",
    "expire_at": 1780000000000
  }
}

响应 400（卡密无效/已用/设备不匹配）:
{
  "code": 400,
  "msg": "该卡密已绑定其他设备"
}
```

**鉴权校验**
```
GET /api/license/verify
Authorization: Bearer {token}
X-Device-ID: {device_id}

响应 200:
{
  "code": 200,
  "data": {
    "valid": true,
    "expire_at": 1780000000000,
    "token": "{refreshed_rsa_token}"
  }
}
```

**解绑设备（管理员发起，或客户端发起换机申请）**
```
POST /api/license/unbind
（需管理员 API Key 或指定客服流程）
```

#### 面向三方卡网（发货 Webhook）

```
POST /api/cards/deliver
Authorization: Bearer {CARDNET_WEBHOOK_SECRET}
Content-Type: application/json

{
  "order_id": "cardnet_order_123",
  "product_id": "sx_monthly",     // 对应本服务端的卡密类型
  "quantity": 1
}

响应 200:
{
  "code": 200,
  "cards": ["SX-XXXX-XXXX-XXXX"]
}
```

### 4.4 Token 设计

```
Token = Base64Url(payload) + "." + RSA-SHA256(Base64Url(payload), TOKEN_PRIVATE_KEY)

payload = {
  "card_key": "SX-XXXX",
  "device_id": "abc123",
  "expire_at": 1780000000000,
  "issued_at": 1720000000000,
  "token_version": 2
}
```

服务端使用私钥签发，客户端只内置公钥，可安全进行离线验签。服务端在线
校验还会回查卡密激活状态、设备绑定和有效期，并换发最新格式 Token。
客户端激活请求使用独立的 `CLIENT_SIGN_SECRET`，不得与 Token 私钥或旧
Token 迁移密钥共用。

发货接口以 `order_id` 为幂等键：卡网重试相同订单时返回首次生成的卡密，
参数不一致则返回冲突，不会重复发卡。

## 5. 客户端设计

### 5.1 当前实现

| 类 | 职责 |
|----|------|
| `LicenseConfig.java` | 接收宿主注入的服务端 URL、激活请求密钥、RSA 公钥与 Debug HMAC 密钥 |
| `SxServerLicenseClient.java` | 使用 `HttpURLConnection` 调用 `/activate` 与 `/verify` |
| `LicenseResult.java` | 统一服务端调用结果 |
| `LicenseManager.java` | DEV/服务端授权分流、Token 持久化、离线验签与后台刷新 |
| `DeviceFingerprint.java` | 在宿主主进程生成设备指纹 |

Debug 构建允许 `SX-DEV-YYYYMMDD` 走本地 HMAC Token；普通卡密和 Release
构建只走自建服务端。应用启动时先对 RSA Token 做本地验签，再在后台调用
`/verify` 回查服务端状态和刷新 Token。

### 5.2 本地 Token 结构

授权记录以 JSON 存入 `SxPrefs.KEY_LICENSE`：

```json
{
  "source": "server",
  "card": "SX-XXXX",
  "token": "{base64url_payload}.{rsa_signature}",
  "expireAt": 1780000000000,
  "deviceId": "abc123"
}
```

当前存储介质是应用私有的 `MODE_PRIVATE SharedPreferences`，不是
`EncryptedSharedPreferences`。静态加密属于 P-B 安全加固项。

### 5.3 `isValid()` 逻辑

```text
读取授权记录
  ├─ source=dev 且为 Debug → HMAC 验签 + deviceId + expireAt
  └─ source=server
       ├─ RSA-SHA256 公钥验签
       ├─ 校验 payload.device_id/card_key/expire_at 与本地记录一致
       └─ 使用 TimeGuard 可信时间检查永久授权或到期时间
```

### 5.4 SplashActivity 校验流程

```
App 启动
  ├─ isValid() = true  ──► 进主界面
  │                        └─ 后台异步 verify() 刷新 expireAt（不阻塞启动）
  └─ isValid() = false ──► 跳 LicenseActivity（激活页）
```

### 5.5 设备指纹

设备指纹必须在宿主主进程、Hook 层生效前读取。当前
`DeviceFingerprint.java` 对 Android ID 做 SHA-256，避免上传原始标识。

## 7. 验收标准

| 场景 | 期望行为 |
|------|---------|
| 三方卡网发货 Webhook 调服务端 | 服务端返回卡密，卡网自动发给用户 |
| 用户输入有效卡密激活 | 客户端调服务端 → 绑定成功 → 返回 Token → 本地存储 → 进主界面 |
| 重复设备激活同一卡密 | 正常（保持原绑定并重新签发当前格式 Token） |
| 不同设备激活同一卡密 | 服务端返回「已绑定其他设备」错误 |
| Token 有效，无网络 | 本地校验通过，正常进主界面 |
| Token 过期 | 跳激活页 |
| 管理员后台解绑设备 | 用户重新激活可绑定新设备 |
| DEV 卡密在 release 包 | 拒绝（仅 Debug 构建允许本地 DEV 路径） |
