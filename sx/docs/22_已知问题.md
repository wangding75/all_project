## 二、 已知技术限制与边界 (Known Limitations)

### 1. 虚拟相机 (Virtual Camera) 限制

- **支持范围**：仅支持标准 `Camera.PreviewCallback` 级别的 NV21/YUV 图像帧拦截与替换。
- **暂不支持**：
  - Camera2 API 的全量 Surface / SurfaceTexture 纹理强行替换；
  - 视频循环解码（MP4 硬件解码动态渲染）；
  - 3D/AR 等高阶相机硬件底层操作。
- **详见文档**：`docs/18_Camera策略限制说明.md`。

### 2. 卡密与授权机制

- **当前实现**：普通卡密通过 FastAPI 服务端激活并绑定设备；服务端使用 RSA 私钥签发 Token，客户端内置公钥离线验签，并在启动后在线刷新状态。
- **DEV 卡密**：`SX-DEV-20991231` (有效期至 2099-12-31，用于内测与调试)。
- **限制**：DEV 卡密仅在 Debug 构建开放；生产部署必须替换客户端请求密钥和 RSA 密钥对。防回拨时间通过 HTTPS Date 锚点异步校验。

### 3. 钉钉（目标 App 首发）— 当前不可用

- **状态（2026-07-30）**：在 MuMu Android 12 + 钉钉 7.8.10 上 **不能稳定启动**；未过 DT-01（登录页/无必现崩溃）。
- **表现**：秒退、进程 signal 11、或进程被拖活但无登录页 / 高 CPU。
- **主因**：隐私检测失败 + 导出组件启动检测（`ExportedActivityUtils` → `System.exit`）+ native `SIGSEGV(SI_USER)` 自杀；与历史 GC/JNI 局部引用长时崩不是同一类。
- **口径**：未测 / 未过不得宣称钉钉可用。
- **详见**：`docs/26_钉钉专项现象与问题.md`。

### 4. 系统与 ROM 兼容性限制

- **Android 版本适配是刚需**：VA/BlackBox 依赖 Hook + Proxy 组件，Android 12（ActivityClient / LaunchActivityItem）、14（`bindServiceInstance`）、16 等路径均需分流维护。详见 `docs/crash-analysis/real-device-issues-log.md` 问题 3。
- **Android 14/15/16**：已在真机（HyperOS / API 36）完成系统时钟 `com.android.deskclock` 启动保持修复；**不代表**全机型、全系统 App 已覆盖。
- **定制 ROM 差异**：MIUI/HyperOS、ColorOS、OriginOS、Harmony 等可能改变系统 App 行为、后台策略与权限模型，需真机专项回归；非“每个厂商 UI 做一套产品”，而是兼容性清单 + 按需补丁。
- **VA 共性**：同类问题在 VirtualApp 等方案同样存在，属技术路线通病，需持续跟版本与 ROM。

### 5. 强检测应用与高阶防封

- **定位**：当前提供基础反 Mock (`isFromMock=false`)、设备全字段伪装、WiFi/基站信息伪装。
- **限制**：未包含高级内核级防检测（如 Kernel VMP、Syscall 绕过、Hardware-level Attestation），遇到金融级/强反作弊检测 App 可能存在被检测到的风险。

### 6. 相机跨进程数据读取路径白名单限制 (Camera Path Security Whitelist)

- **实现说明**：`ConfigProvider.get_camera_bytes` 已限制为仅允许读取 Host 应用的专用相机目录（`getExternalFilesDir("camera")`、`getFilesDir()/camera` 以及 cache 目录），拒绝任意文件路径读取请求。
- **限制**：选择媒体文件时需放置在允许的相机沙箱存储路径下。

### 7. 实机/模拟器点按回归后置说明

- **当前状态**：ST-1 已在 MUMU Android 12 模拟器完成 G1～G5 主路径点按并通过，详见 `docs/21_回归记录.md`。更完整的模拟器覆盖、通用真机 ST-2 与钉钉专项仍后置到统一设备测试波次。

### 8. 授权 Token 本地静态存储

- **当前实现**：授权 Token 存入应用私有的 `MODE_PRIVATE SharedPreferences`，其他普通应用不能直接读取。
- **限制**：当前没有使用 `EncryptedSharedPreferences` 或等价的静态加密；Root、调试注入或设备备份场景下仍可能暴露，列入 Epic P-B 安全加固。

### 9. targetSdk 34 与高版本系统适配
- **状态**：构建配置已将 `targetSdk` / `compileSdk` 升级至 `34`，并补全 `foregroundServiceType`、动态 Receiver 隔离及 Android 14+ 隐式 Intent 限制。
- **限制**：targetSdk 升级不等于 Android 15/16 全量兼容性已通过；相关系统仍需纳入 ST-2/后续设备矩阵实测。

### 10. 重度 C++ 渲染内核应用（夸克/UC浏览器）沙盒长效兼容性与 C++ JNI 内存泄露问题

- **现象与定位**：夸克浏览器等集成自研 C++ WebView 渲染内核的应用，在沙盒环境中进入首页 ~30 秒稳定发生 C++ Native 崩溃。
- **已完成定位与彻底修复**：
  1. 修复 `UnixFileSystemHook.cpp` 与 `RuntimeHook.cpp` JNI 局部引用泄露 (`env->DeleteLocalRef`)。
  2. 增加 `IO.cpp` C++ 纯 Native 路径重定向，解决动态 `.so` 插件（`libmnnpybridge.so`）加载失败。
  3. 修复 `JniHook.cpp` 中 `ArtMethod` Flags 篡改，恢复 Native Bridge (`libndk_translation`) JNI 寄存器对齐。
  4. 净化 `BActivityThread.java` 中 WebView 数据目录后缀中的非法冒号。
- **验证结果**：通过 3 轮 20 分钟长效稳定性验证（第 1 轮连续运行 1.7+ 小时无崩溃），已彻底解决。
- **详见文档**：`docs/crash-analysis/quark-browser-crash-root-cause-and-fix.md`。
