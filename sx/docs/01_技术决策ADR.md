# 技术决策记录 (ADR)

## ADR-001：沙箱引擎选型

| 字段 | 内容 |
|------|------|
| 状态 | **已接受** |
| 日期 | 2026-07-20 |
| 决策 | 采用 **BlackBox 自维护 fork** 作为主沙箱引擎 |

### 背景

闪现需要对标星盒的多开 + 环境伪装。星盒为 VA 系商业级引擎（`com.lody.virtual.*` + `libvv` + Pine）。团队 **不采购 VA 商业授权**，需选择可合法维护的底座。

### 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 商业 VA 授权 | 适配与能力最强，与 xh 最像 | 费用与商务 | 本期不选 |
| 2017 开源 VA | 包名熟悉 | 停更，无法支撑 10+ | 否决 |
| 社区泄露/不明 VA | 看似能力强 | 侵权与质量风险 | **否决** |
| 两仪 Twoyi | 隔离强 | 重、非多开产品形态 | 否决为主引擎 |
| **BlackBox fork** | 开源可维护、多开模型正确 | 新系统需自适配 | **采用** |

### 后果

- 产品层通过 `SandboxEngine` 抽象，避免写死 BB 类名  
- xh 仅作 **行为规格与 UI 参考**，不拷贝其 so/业务加固逻辑  
- 需预留引擎适配人力（Android 12+）

## ADR-002：Hook 策略

| 字段 | 内容 |
|------|------|
| 状态 | **已接受** |
| 决策 | **沙箱内 Hook 为主**；LSPosed 模块为可选旁路 |

### 说明

- 星盒在 VA 虚拟进程内用 Pine 等做设备/相机等注入  
- 闪现：分身启动链路中安装 Hook，读取分身级 Profile  
- 不把「用户必须安装 LSPosed」作为 P0 前提  
- 可选：同一套配置通过 XSharedPreferences 供 LSPosed 读取（调试/进阶）

## ADR-003：UI 策略

| 字段 | 内容 |
|------|------|
| 状态 | **已接受** |
| 决策 | **信息架构与页面流程参照星盒 (xh)**，视觉与品牌自有 |

### 参照范围

- 启动 → 激活/主页 → 底部 Tab（首页 / 应用 / 我的）  
- 虚拟设置分入口：定位、设备、WiFi/蓝牙、相机/相册/视频  
- 应用列表长按菜单：启动、克隆、快捷方式、独立设置、清除、卸载  
- 文案逻辑对齐 xh strings（改品牌为「闪现」）

### 不参照

- 星盒图标/启动图/加固壳  
- 激活服务器协议与卡密算法（自研）  
- 内嵌广告/分享文案中的他牌产品名

## ADR-006：授权与加固

| 字段 | 内容 |
|------|------|
| 状态 | **已接受** |
| 决策 | 一期：本地卡密 + HMAC 离线 Token + 网络授时防回拨；加固后置 |

开发卡密格式建议：`SX-DEV-YYYYMMDD`（到期日）。  
R8/商业加固、Dex2C/VMP 放入发布阶段，不阻塞功能开发。

## ADR-007：与 xh 的关系

| 允许 | 禁止 |
|------|------|
| 对照 PRD、页面流、Hook 点、Manifest 形态 | 整包拷贝 `com.lody.virtual` / `libvv` 作为闪现引擎 |
| 参考 spoofer_project 的 Mock 定位实现思路 | 使用 ActivationBypass 类逻辑针对星盒 |
| 自研等价 API | 再分发星盒脱壳源码为产品 |

```
引擎   = BlackBox fork（自维护）

Hook   = 沙箱内优先
```
