## 1. 现象（用户侧 / 实测）

| 现象 | 说明 |
|------|------|
| SX 内打开钉钉闪退 | 启动后很快退出，回到 SX 主界面 |
| 进程秒死或反复拉起 | 常见数秒内 `signal 11`；或 PID 频繁变化（崩溃重启循环） |
| 强行「拖活」后仍不可用 | 加 anti-suicide 后曾出现 **同一 PID 存活约 10 分钟**，但 **无登录页**、`mCurrentFocus` 为空、**CPU 极高**（半死进程） |
| 启动方式 | 沙箱内启动 / `ShortcutLaunchActivity` + `package_name=com.alibaba.android.rimet` + `user_id=0` |

## 3. 问题归类

### 3.1 主因：钉钉反多开 / 启动门禁

| 门禁 | 行为 | 结果 |
|------|------|------|
| 隐私协议 | `checkPrivacyPolicy` 失败（前台） | 走失败分支，完整初始化被短路 |
| 导出组件启动 | `ExportedActivityUtils.a` | `System.exit(0)` |
| Native 自杀 | `kill(self, SIGSEGV)` → `SI_USER` | 进程被杀；tombstone 常在 houdini 翻译路径，Java `Process`/`Os` Hook 常拦不住 |

### 3.2 诱因：沙箱身份暴露

- `getCallingPackage` 等在无沙箱内 caller 时，曾 **回落宿主包名** `com.sx.app.debug`（多开特征）
- 真实进程名 / cmdline 为 `com.sx.app.debug:p*`，与虚拟包名不一致
- Referrer / launched-from 等若泄漏宿主，易触发「异常 exported / 误装」类判定

### 3.3 环境因素

| 因素 | 影响 |
|------|------|
| MuMu Android 12 + houdini | arm64 钉钉走翻译层；自杀栈难符号化；行为更脆 |
| 仅 base split | 设备上 `splits=[base]`，启动期仍见 `SplitCompatBack` 线程相关异常 |

### 3.4 修复尝试中的次生问题

| 手段 | 结果 |
|------|------|
| 仅拦截 `System.exit` | 继续执行 → **Doraemon 未 init**（`please call Doraemon init method first`） |
| 拦截 SI_USER / anti-suicide | 进程可活，但 **无可用 UI**，或 **信号风暴 + 高 CPU 空转** |
| 过度 Hook（`Thread.start` / `Os.kill` 等） | 行为更不稳定，甚至更易触发检测 |
| `sigprocmask` 屏蔽 SIGSEGV | 与同步真实 SIGSEGV 叠加时，易出现 **进程反复 signal 11 重启** |

## 4. 已落地改动（方向参考，未过验收）

| 位置 | 内容 |
|------|------|
| `ActivityStack` | 外部启动时 `getCallingPackage` / `getCallingActivity` 不再泄漏 hostPkg |
| `BActivityThread` | `ReferrerIntent` 使用访客包名 |
| `DingTalkHook` + `SpoofRuntime` | 隐私 SP、强制 `checkPrivacyPolicy`、跳过 `ExportedActivityUtils.a`、拦 `System`/`Runtime.exit` 等 |
| `BoxCore.cpp` | anti-suicide：处理人为 `SIGSEGV`/`SIGABRT`（`SI_USER`） |

**状态：** 有助于理解与部分缓解秒退，**不足以** 宣称 DT-01 通过。

## 5. 与星盒 (xh) 对照（为何那边「往往能开」）

对照仓库：`D:\github\xh` 反编译与交接文档（非本机 A12 已完整验收 xh 登录页）。

| 维度 | xh（星盒） | SX（当前） |
|------|------------|------------|
| 底座 | VirtualApp 商业定制（`libvv` + pine） | BlackBox + 自研 spoof |
| 钉钉 | **一等公民**（`VDingManager` / `VDingConfig` / 业务 Hook） | 通用启动 + 临时钉钉 Hook |
| 身份 | 长期整包 PM/AM/IO 伪装 | 曾泄漏宿主；专项仍不完整 |
| 策略 | 尽量 **不触发** 门禁 | 触发后 **事后硬挡**（exit / SI_USER） |
| 环境 | 文档推荐 **Android 9**；A12 有 VA native 偏移问题 | 当前主测 **MuMu A12 + houdini** |

**要点：** xh 能稳，多半是身份 + 钉钉专项 + 环境红利；不能简单当成「同机 A12 上 xh 一定满分」。

## 7. 后续攻坚优先级（建议）

1. **少触发检测**：启动身份链（calling / referrer / 进程表象）对齐 VA 级，而不是只靠 anti-suicide。  
2. **隐私一次通过**：不仅 SP，还要 `LauncherApplication.checkPrivacyPolicy` 等与初始化顺序一致，避免 Doraemon 短路。  
3. **导出门禁**：`ExportedActivityUtils` 与正常桌面启动语义对齐。  
4. **Native 自杀**：在确认不进 kill 循环的前提下处理 `SI_USER`；避免信号风暴拖尸进程。  
5. **对照**：同钉钉版本下 xh UI 成功启动 log 与 SX 失败 log 逐段 diff。  
6. **环境**：优先真机 arm64 或 Android 9/10 复测，降低 houdini 干扰。

失败项必须进兼容表；**未测不得宣称钉钉可用**（与 docs/00、docs/25 口径一致）。
