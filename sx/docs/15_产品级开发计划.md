## 1. 产品级目标

交付 **可商业分发/销售的 v1.0**，在通用机型策略下满足：

1. 多开与伪装/相机等核心卖点 **稳定可用**  
2. **商业授权**闭环（发卡、绑定、验票、到期）  
3. **安全与合规**达到分发底线  
4. **可观测、可发版、可运维**  

### 1.1 机型与测试（继承 14）

- **机型：** 通用机型优先，不承诺全品牌定制 ROM。  
- **顺序：** **模拟器通过 → 再通用真机**；真机不过不发布。  
- 产品级阶段再逐步扩大机型与目标 App 抽样，仍以通用基线为门禁。

## 3. Epic 详细任务

### Epic P-A — 商业授权（P0，已完成）

当前实现采用 FastAPI + SQLite 服务端、RSA-SHA256 Token、客户端公钥离线
验签、`order_id` 发货幂等和管理员解绑。详细现状见
[29_商业授权技术方案.md](./29_商业授权技术方案.md)。

| ID | 任务 | 产出 | 验收 |
|----|------|------|------|
| P-A01 | 授权方案设计（卡密/订阅、绑定维度） | 方案一页纸 | 评审通过 |
| P-A02 | 服务端：发卡、核销、设备绑定、解绑 | API + 管理端最小可用 | 可造卡、可绑、可查 |
| P-A03 | 客户端：登录/激活改走服务端 + 离线 Token | 替换纯 DEV 主路径 | 无网限时可用、有网续期 |
| P-A04 | 防时钟回拨与验签 hardening | 与 TimeGuard 整合 | 回拨无法续期 |
| P-A05 | 客服解绑/换机流程 | 操作说明 + 后台能力 | 可完成一次解绑演示 |
| P-A06 | DEV 卡密仅保留 debug | Build 区分 | release 不接受任意 DEV 滥发 |

### Epic P-B — 安全加固（P0）

| ID | 任务 | 产出 | 验收 |
|----|------|------|------|
| P-B01 | Release 签名与包体规范 | 签名配置文档 | 可打 signed release |
| P-B02 | R8 全量 + keep 规则完善 | 映射文件归档 | release 安装主路径通过 |
| P-B03 | 商业加固方案选型与接入 | 加固包 | 约定检测项通过 |
| P-B04 | 防二次打包/签名校验 | 启动校验 | 重签包拒绝运行（约定行为） |
| P-B05 | 客户端请求密钥治理、Token 本地静态加密与密钥轮换 | 方案落地 | 评审通过 |

### Epic P-C — 质量 SLA（P0）

| ID | 任务 | 产出 | 验收 |
|----|------|------|------|
| P-C01 | 冻结「通用机型 + 系统」发布矩阵 | 矩阵表 | 写入发布说明 |
| P-C02 | 冒烟脚本/清单（模拟器 + 真机） | checklist | 每次发版可勾选 |
| P-C03 | 多开成功率/崩溃率目标与统计方式 | KPI 定义 | 如：主矩阵启动成功率 ≥ 约定值 |
| P-C04 | 目标 App 抽检清单（按卖点） | 清单 + 结果 | 至少 N 个 App 有记录 |
| P-C05 | 回归节奏（发版前必跑） | 流程 | 未跑回归不发版 |

**测试顺序强制：** 模拟器全绿 → 通用真机全绿 → 发版候选。
